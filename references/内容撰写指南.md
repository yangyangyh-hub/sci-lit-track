# 内容撰写指南（每个方向一个 JSON）

报告的文字层由 agent 撰写，`build_report.py` 只负责拼装。本文件定义写什么、怎么写、怎么校验。

> **2026-11-20 变更（v2.1）**：每篇不再写「背景 / 方法 / 主要结果 / 结论」四段，
> 改为**把原文摘要整段译成中文**（`abstract_cn`）。旧四段字段仍被脚本兼容读取，
> 但新一期一律用 `abstract_cn`。

---

## 1. 文件与格式

每方向一个文件：`<项目>/content/d1.json` … `d5.json`（键是方向 id）。

```json
{
  "1": [
    {
      "doi": "10.1186/s12711-026-01095-0",
      "title_cn": "扩展猪代谢组数量性状基因座目录",
      "abstract_cn": "结构变异通常需借助长读长测序才能有效检出，但此类数据稀缺……（整段译文，与原文同序）"
    }
  ]
}
```

每篇**只有两个正文字段**：`title_cn`（中文译题）+ `abstract_cn`（摘要整段中译）。

**`doi` 必须与 `result.json` 里该篇的 `doi` 完全一致（小写）**——脚本按 DOI 做匹配，对不上就会显示「摘要中译待补」。
`verify_doi.py` 修正过的 DOI，以修正后的为准；留空的就写空串 `""`。

**摘要原文在哪**：`result.json` → `final.<方向 id>.picked[i].abstract`。直接取这篇的 `abstract` 字段翻译，
不要凭标题猜内容，也不要用记忆里的知识补摘要没写的东西。

---

## 2. 摘要怎么译

一句话原则：**译文要能替代读原文摘要**——读者只看译文，就相当于看过了英文摘要。

| 要做 | 不要做 |
|---|---|
| 按摘要原有顺序逐句译，原文怎么起承就怎么起承 | 把摘要重排成「背景→方法→结果→结论」四段小标题 |
| 完整译出整段，一句不落 | 只挑「有意思的结论」译，略掉方法与数值 |
| 数字、样本量、基因/菌种/蛋白名、统计量照原文（`89 900 个插入`、`P = 3.2×10⁻⁹`） | 四舍五入、换算成「约」「近」 |
| 缩写首次出现给中文全称 + 原文缩写：「全基因组关联分析（genome-wide association study，GWAS）」 | 直接用 GWAS、SNP 不解释（摘要首现处） |
| 保留限定语：`仅在…中`、`不影响…`、`在雄性中`、`与…相关（associated with）` | 把"相关"译成"导致"、把"提示"译成"证明" |
| 一段连续成文，可用分号、句号断句 | 拆成 bullet 列表、加"（1）（2）"编号 |

- **长度随原文**，通常 200–450 字；原文短就短，不必凑字数，也不必压缩。
- 摘要没有小标题时，按语义自然分段即可，**不要替作者造"背景/方法"标签**。
- 只译不改写：不合并同类句、不删重复限定、不加"该研究具有重要意义"这类总结句。
- 摘要里的 `ClinicalTrials.gov NCTxxx`、`trial registration` 等登记信息属于摘要内容，如实译出。

---

## 3. 摘要缺失 / 被截断怎么处理

| 情形 | 处理 |
|---|---|
| 摘要正常 | 整段译完 |
| 摘要里出现 `... [truncated]`、明显断在半句 | 回到 `result.json` 取 `abstract` 全文再译；仍断就照实译到断点，**不补写** |
| `abstract` 字段为空 | `abstract_cn` 写 `原刊未提供摘要`（不要编内容，也不要留空） |
| 只有结构化摘要的部分小标题（如只有 Background） | 有什么译什么，不推测缺失部分 |

**禁止**：用「摘要未提供」搪塞一段其实有内容的摘要——这是最常见的返工点。

---

## 4. 语言与术语

- 书面语，不用第一人称；不出现"本研究团队""我们认为"——一律"该研究/作者"。
- 中文要通顺：英文长句可拆成两三个中文短句，但**不得改变句子之间的因果与限定关系**。
- 物种拉丁名首次出现给中文（`Sus scrofa` → 猪（Sus scrofa））；基因/蛋白名保留原文大小写（FASN、Nrf2、miR-6631-5p）。
- 单位、百分号、上下标照原文（`1.3×10⁻⁹`、`30,628 个比值`、`mg/kg`）。
- 统计表述照原文：`P < 0.05`、`95% CI`、`n = 240`。

---

## 5. 交稿前自检（逐条过）

- [ ] 每篇都有 `title_cn`，且是**中文**（不是英文原题复制）
- [ ] 每篇都有 `abstract_cn`，且是**整段连续译文**（不是四段 bullet、不是要点摘录）
- [ ] 译文顺序与原文摘要一致，没有自己重排
- [ ] 数字、样本量、关键基因/菌种名能回到摘要原文
- [ ] 摘要首现的缩写都给了中文全称
- [ ] 没有"具有重要意义""提供了新思路"式空话，没有替作者做评价
- [ ] 没有把摘要的"推测/相关"写成"证明/导致"
- [ ] 摘要被截断的篇目已回到 `result.json` 取全文
- [ ] DOI 与 result.json 一致（脚本会自动比对，留空的除外）
- [ ] 同一篇没有在两个方向重复出现

---

## 6. 常见返工点

1. **译成四段**：习惯性写成"背景/方法/结果/结论"标签 —— 本版式已取消，改一段到底。
2. **译成摘要要点**：把摘要压成 3 句"核心发现" —— 那是摘录不是翻译，信息会丢。
3. **译题太长**：中文标题控制在 30 字内，副标题可省，但不得改变含义。
4. **丢限定语**：`仅在…中`、`不影响…`、`在雄性中` 删掉就改变了事实。
5. **替作者升华**：结尾自动补一句"为…提供了新思路" —— 摘要没写就不写。
