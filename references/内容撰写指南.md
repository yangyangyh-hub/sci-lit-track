# 内容撰写指南（每个方向一个 JSON）

报告的文字层由 agent 撰写，`build_report.py` 只负责拼装。本文件定义写什么、怎么写、怎么校验。

---

## 1. 文件与格式

每方向一个文件：`<项目>/content/d1.json` … `d5.json`（键是方向 id）。

```json
{
  "1": [
    {
      "doi": "10.1186/s12711-026-01095-0",
      "title_cn": "扩展猪代谢组数量性状基因座目录",
      "bg": "……",
      "method": "……",
      "result": "……",
      "conclusion": "……"
    }
  ]
}
```

**`doi` 必须与 `result.json` 里该篇的 `doi` 完全一致（小写）**——脚本按 DOI 做匹配，对不上就会显示成"待填"。
`verify_doi.py` 修正过的 DOI，以修正后的为准；留空的就写空串 `""`。

---

## 2. 四段怎么写

| 段 | 写什么 | 不要写 |
|---|---|---|
| **背景** | 领域已知事实 + 尚未解决的问题（摘要的 Introduction/Background） | 泛泛的科普套话 |
| **方法** | 材料/样本量/分组/关键技术/统计方法，数字照原文 | "采用了先进的方法" |
| **主要结果** | 核心发现 + 关键数值（P 值、SFC、FST、剂量等），按摘要顺序 | 把结果升格成结论 |
| **结论** | 摘要自己的 Conclusion 段；没有就写「摘要未提供」 | 自己替作者总结意义/展望 |

- 每段 **1–3 句**，书面语，不用第一人称。
- 总长度控制在 200–400 字/篇；**信息密度优先于篇幅**。

---

## 3. 「摘要未提供」的正确用法

只在**摘要确实没有对应内容**时使用，写法固定为：`摘要未提供`（可加限定，如「摘要未提供具体数值」「摘要未提供独立结论段」）。

**常见误用**：
- ❌ 摘要写得很简略，就用「摘要未提供」搪塞 → 应该把摘要里有的信息写全。
- ❌ 摘要有 Results 但无 Conclusion 标题，就跳过结论 → 写「摘要未提供独立结论段」，并从结果段**不引申**地收一句。
- ❌ 摘要因抓取被截断（`... [truncated]`）就写「摘要未提供」→ 应回到 `result.json` 的 `abstract` 字段取全文。

---

## 4. 语言与术语

- 首次出现的缩写必须给中文全称：「全基因组关联研究（genome-wide association study，GWAS）」。
- 基因/蛋白名保留原文大小写（FASN、Nrf2、miR-6631-5p）；物种拉丁名首次给中文。
- 数字与单位照原文（`1.3×10⁻⁹`、`248 种代谢物`、`30,628 个比值`），不要四舍五入。
- **区分相关与因果**：摘要写 "associated with" 就不要译成"导致"。
- 不要出现"本研究团队""我们认为"——一律用"该研究/作者"。

---

## 5. 交稿前自检（逐条过）

- [ ] 每篇都有 `title_cn`，且是**中文**（不是英文原题复制）
- [ ] 四段齐全，或明确写了「摘要未提供」
- [ ] DOI 与 result.json 一致（脚本会自动比对，留空的除外）
- [ ] 数字、样本量、关键基因名能回到摘要原文
- [ ] 没有"具有重要意义""提供了新思路"式空话
- [ ] 没有把摘要的"推测"写成"证明"
- [ ] 同一篇没有在两个方向重复出现

---

## 6. 常见返工点

1. **译题太长**：中文标题控制在 30 字内，副标题可省，但不得改变含义。
2. **方法段抄成结果段**：方法只写"怎么做的"，不写"做出什么"。
3. **结论段写成评论**：`结论` 只复述作者结论；评价性判断不写进报告。
4. **漏掉限定语**：`仅在…中`、`不影响…`、`在雄性中` 这类限定条件必须保留，删掉就改变了事实。
